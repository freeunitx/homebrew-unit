## 🩻 5. TODO-4: публиковать артефакты проверенного run

Приоритет: **P1**. Статус: **исправлено**.

Файлы:

- `.github/workflows/publish-commit-bottles.yml:43-44` — выходы `run-id` и `head-sha`;
- `.github/workflows/publish-commit-bottles.yml:70-86` — выбор run в `precheck`;
- `.github/workflows/publish-commit-bottles.yml:131-146` — повторная проверка в `upload`;
- `.github/workflows/publish-commit-bottles.yml:172` — `--head-sha` в `brew pr-pull`.

### Что было

`precheck` записывал `run-id`, но задание `upload` его не использовало. `brew pr-pull` сам выбирает последний check suite. Проверка и публикация могли относиться к разным run.

### Что подтвердил исходник Homebrew 7.0.16

- У `brew pr-pull` нет параметра с номером run. Есть только `--head-sha`.
- `GitHub.get_workflow_run` читает последний коммит PR и его check suites.
- `GitHub.get_artifact_urls` берет артефакты из **последнего** check suite. Вывод этого run может быть любым, не только `success`.
- При `--head-sha` команда останавливается, если HEAD PR отличается.

### 🩹 Исправление

- [x] `precheck` выбирает последний **завершенный** run и требует `success`. Старый успешный run рядом с новым провальным больше не проходит.
- [x] `precheck` передает `head-sha` и `run-id` в `upload`.
- [x] `upload` повторяет выбор последнего завершенного run. При несовпадении с `run-id` публикация останавливается.
- [x] `brew pr-pull` получает `--head-sha="${HEAD_SHA}"`.
- [ ] Проверка «скачать артефакты локально и опубликовать без `pr-pull`» не сделана. Это меняет модель публикации и выходит за рамку исправления.

### 🧪 Проверка

- [ ] Запустите второй build между `precheck` и `upload`.
- [ ] Проверьте остановку публикации при появлении нового run.
